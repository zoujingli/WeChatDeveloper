# AI 开发规则

本流程适用于源代码、测试、用户文档、Composer 配置和 CI 的变更。按顺序执行；每一步达到完成条件后再进入下一步。

## 1. 建立上下文

先阅读 `README.md`、`docs/design.md` 和与任务相关的主题文档，再检查实际实现、对应测试以及调用方可见入口。存在 `CONTEXT.md` 或相关 ADR 时，按 `docs/agents/domain.md` 一并读取。

Issue 和规格描述目标，代码、测试与配置描述当前状态。两者不一致时，明确指出差异并以已确认的验收边界为准。

**完成条件**：受影响的公开入口、配置契约、异常、信任边界、测试文件和用户文档均已定位。

## 2. 收敛变更设计

保持 SDK 的调用层边界：SDK 负责配置校验、认证、HTTP、缓存、签名和验签；通知、消息、授权页面、业务字段加解密、订单、幂等、持久化、日志告警和业务状态机留给调用方。

每个出站协议使用对应的通道 `*Client::mk(具体配置)->call(Request)->Response`。通道 Client 各自分开，公共行为复用 `ChannelInterface`、`We\Common` 调用类型和内部调用管线；不得增加按配置类型分派的根 Client。业务 API 只提供官方相对路径或 Gateway 方法与请求体，不增加退款、下单、账号信息等具名方法。

六个 Client 与 Config 使用 `docs/api.md` 的场景映射作为唯一命名标准；重命名直接迁移，不增加别名类或兼容命名空间。

`src/` 根目录只放六个通道 Client，并使用 `We` 根命名空间。其他源码按复用范围归属：跨微信与支付宝复用的调用类型、基类、契约和基础设施放入 `Common`；微信生态复用类型放入 `Wechat/Common`，支付宝生态复用类型放入 `Alipay/Common`；六个具名 Config 直接放在 `Wechat` 或 `Alipay` 生态根目录。只有单一通道另有专属契约或实现时才建立同名前缀目录，例如 `Wechat/WxOpen`；非公开实现放入所属模块的 `Internal`。不得建立顶层 `Config`、`Contract`、`Provider`、`Support`、`Protocol` 或 `Transport` 目录横切生态。

优先扩展既有接口：通道实现 `ChannelInterface::call()`，HTTP 传输实现 `HttpTransportInterface`，签名、信任材料与 Token 分别通过 Provider 解析，运行态缓存和开放平台授权方存储继续实现 `StoreCacheInterface` 与 `StoreTokenInterface`。公共接口不得透传 Guzzle 选项。

**完成条件**：变更面已缩到满足验收要求的最小范围，并能通过调用方可见行为进行验证。

## 3. 实现并守住不变量

- PHP 文件使用 `strict_types=1`、原生参数类型和返回类型；数组形状、泛型或工具无法推导的约束再用 PHPDoc 表达。
- 配置对象在构造和 `fromArray()` 路径上执行同等校验。无效输入通过 `SdkException` 体系失败，避免泄漏偶发的 `TypeError`、OpenSSL 警告或底层传输异常。
- 平台故障保留可诊断的异常类型与 `context()`，上下文只包含排障所需数据，不写入私钥、API 密钥、完整凭证或其他敏感值。
- 认证、签名、验签、支付、URL 或缓存变更必须阅读 `docs/design.md` 及对应主题文档，并维持其中定义的校验顺序和信任边界。安全配置采用失败关闭；任何放宽都必须是明确、可测试且已获确认的产品决定。
- HTTP 传输通过 `Runtime` 注入；生产默认值留在 Guzzle 适配器内，测试使用记录型传输适配器替换外部平台边界。
- 公共契约、非显然行为及安全或并发原因使用简洁中文 PHPDoc/注释。修改行为时同步更新相关注释；保留仍然有效的设计理由。文件头、作者声明和重复原生类型的无信息注释不属于开发文档。
- 保持与任务无关的代码和用户改动原样；机械格式化只作用于配置规定的范围。

**完成条件**：每个新增或变化的输入均有验证路径，每个失败分支进入 SDK 异常体系，外部依赖可替换，注释与实现一致，信任边界没有隐式放宽。

## 4. 验证行为

先运行最接近变更的测试文件。公开行为变化必须增加或调整回归测试，并优先经过对应通道的 `*Client::mk()`、配置对象或公开契约断言结果。

测试遵循 `docs/testing.md`：不连接真实微信或支付宝账号；通过 `Runtime` 注入记录型传输适配器；从通道 `*Client::mk()->call()` 和 `Response` 解析方法断言调用方可见结果，并只在 HTTP 传输接口观察最终 PSR-7 请求。安全变更同时覆盖成功、拒绝、边界值和降级路径。

**完成条件**：目标测试覆盖正常路径、预期失败和受影响的边界条件，并在修改后通过。

## 5. 同步文档

公开入口、配置字段、异常、安全默认值或调用方式变化时，更新 README 和对应主题文档；破坏性变化同时更新 `docs/migration-2.0.md`。文档只保留一处权威解释，其他位置通过链接导航。

文档和代码注释遵守 `docs/style-guide.md`。PHP 示例必须语法完整并可被文档测试解析，不使用省略号代替表达式，不包含真实凭证。项目术语或长期架构决策按 `docs/agents/domain.md` 处理；既有设计说明不得机械复制成术语或 ADR。

同时检查 `CONTEXT.md`、相关 ADR、协议 research 和 `docs/agents/` 指针。只有领域词汇、长期决策、协议事实或代理规则实际变化时才更新对应文件；实现目录和类签名继续由设计、公开 API 与配置文档负责。

同步前从源码反射或逐项列出变化后的公开类型、非内部公开方法、构造参数和默认值。`docs/api.md` 记录公开签名与契约，平台主题文档记录协议差异，配置文档记录构造与数组入口；接口方法 PHPDoc 定义实现责任，具体实现不重复同一契约。

**完成条件**：每个变化的公开类型、方法、配置、安全行为、异常或迁移影响都有且只有一个权威说明；领域词汇、ADR、research 和代理规则已逐项判定是否受影响；完整命名空间、签名、默认值、导航和示例均与实现一致。

## 6. 组织代码提交

提交采用原子功能边界：一笔提交只完成一个可独立解释、验证和回滚的目标。实现与直接回归测试放在同一提交；依赖与 CI、用户文档、代理规则分别提交。实现稳定后再依据实际行为更新文档，文档不得提前承诺尚未落地的能力。

前端行为变更需要把前端源码以及仓库明确纳入版本控制的构建产物、类型文件或资源清单放入同一功能提交，保持本地前端与提交内容一致。本仓库没有前端目录时，该分支不适用。

提交标题使用 `<type>(<scope>): <中文动作描述>`：

- `feat`：新增公开能力；
- `fix`：修复缺陷或安全边界；
- `refactor`：不改变公开行为的结构调整；
- `docs`：用户文档、PHPDoc 或代理文档；
- `test`：不伴随行为修改的测试变更；
- `chore`：依赖、工具或维护任务；
- `build` / `ci` / `perf`：构建、持续集成或性能专项。

`scope` 使用简短、稳定的小写模块名，例如 `config`、`alipay`、`cache`、`wechat`、`deps`、`reference`、`agent`。标题使用中文动宾结构说明结果，不写句号，不使用“更新代码”“修复问题”等无法识别边界的泛化描述。

非平凡提交必须提供中文正文，依次说明：问题或动机、实际行为与边界、验证方式及兼容性影响。正文记录“为什么”和不可见约束，文件清单与代码细节由 diff 自身表达。

提交前只暂存当前功能涉及的文件或 hunk，并执行：

```bash
git diff --cached --check
git diff --cached --stat
git diff --cached
```

检查暂存区不含无关改动、敏感信息、调试残留或其他功能。存在依赖关系时，提交顺序为基础契约、功能实现、依赖/CI、用户文档、代理规则。推送、打标签、创建 Release 或发布包必须获得当前任务的明确授权。

**完成条件**：每笔提交只有一个功能边界，标题具有正确前缀、稳定 scope 和中文动作描述，正文覆盖动机、行为、验证与兼容性；目标测试已通过，暂存区已逐项复核，未执行未授权的远端操作。

## 7. 执行质量门禁

提交或交付前执行：

```bash
composer cs:fix
composer cs:check
composer analyse
composer validate --strict
composer audit --locked
composer test
git diff --check
```

`composer cs:fix` 会修改文件；运行后重新检查 diff，确认格式化结果仍在任务范围内。依赖或 CI 变更还要核对 `.github/workflows/ci.yml` 的 PHP 8.1–8.4 矩阵和 PHP 8.1 最低依赖门禁。

**完成条件**：所有适用命令以零退出码结束，最终 diff 不包含无关改动、敏感信息、调试残留或与实现冲突的文档。无法执行的门禁必须在交付说明中列明原因和剩余风险。

## 按任务读取的事实源

| 变更分支 | 必须读取 |
| --- | --- |
| 模块边界、扩展接缝、安全或 URL | `docs/design.md` |
| 配置字段、凭证或密钥 | `docs/configuration.md` |
| 缓存键、TTL、刷新锁或适配器 | `docs/cache.md` |
| 微信公众号、小程序或微信开放平台 | `docs/wechat.md` |
| 微信支付、验签或账单 | `docs/payments.md` |
| 支付宝开放平台或支付 | `docs/alipay.md` |
| 异常类型或诊断上下文 | `docs/exceptions.md` |
| 测试结构、环境或质量门禁 | `docs/testing.md` |
| 公开说明、PHPDoc、注释或异常消息 | `docs/style-guide.md` |
| 1.x 兼容或 2.0 破坏性变化 | `docs/migration-2.0.md` |
